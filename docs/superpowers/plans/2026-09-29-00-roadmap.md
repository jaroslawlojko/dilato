## Carried from plan 1 (read before writing plans 2 and 3)

**Installed versions:** Expo SDK 57, React Native 0.86, React 19.2, TypeScript 6, Jest 29 (`jest-expo` 57). Install anything new with `npx expo install`. TypeScript 6 does not auto-include `@types/*`: `app/tsconfig.json` lists `"types": ["jest", "node"]`; split a test-only tsconfig when UI code lands.

**Caller contract of `src/domain` (plan 2 puts this sequence in `ChallengeService`):**

1. On every app open / foreground, and before any read or transition: `advance(ch, now)` on the open challenge and persist it when `advance(ch, now) !== ch` (it returns the same object when nothing changed; `refresh`/`rollover` are internal); then `isNewRecord` for a challenge that `advance` just closed by rollover; then `newBadges`; then `needsConfirmation`; only then `markSeen`.
2. Never call `markSeen` while a confirmation is pending and unanswered. Do call it when the foreground timer witnesses `now ≥ targetAt`. Until plan 5 builds the "Nadal trwa?" sheet, do not call `markSeen` blindly on open. `addOvertime`, `finishForToday` and `interrupt` also set `lastSeenAt`, which dismisses a pending confirmation — show the sheet before offering those actions.
3. `startChallenge` does not check history: call `canStartToday(all, now)` first and enforce unique `(user_id, day)` in SQLite. An `achieved` challenge (24 h goal, or an overtime block that crossed 04:00) blocks today's start until "Na dziś wystarczy" — S03 needs that path.
4. `new_record` is not part of `newBadges`: call `isNewRecord` exactly once per closing transition (user close, rollover close, `confirmSmokedEarlier`) in the same transaction; the domain does not dedupe `times++`.
5. Run `newBadges` on start and after every transition (and after a full pull in plan 4); `five_mornings` and `wave_master` are evaluated against stored state at `now`.
6. Row mapper validates everything that bypasses TypeScript: `status`, `ladder_key`, `target_kind`, `overtime_block_minutes` (15/30/60), day (`YYYY-MM-DD`) and `HH:mm` strings, invalid dates, `pack_size ≥ 1`. It must also guarantee the `ClosedChallenge` invariant that `isClosed` narrows to: a `completed`/`interrupted` row has `ended_at`, `result_minutes` and `first_cigarette_at`. Timestamps are UTC ISO ↔ `Date`; `day` is a stored local string and is never recomputed.
7. `suggestNext` takes closed challenges oldest-first (`all.filter(isClosed)` sorted by `startedAt` fits its input); wrap the result in `availableSuggestion(s, now)` before showing it.
8. Body-benefit unlocks: persist the highest `bestSmokeFreeMinutes` ever reached and never lower it (spec §4.8).
9. `BadgeContext.totalSavings` = `savings({ totalMinutes: totalResultMinutes(all), … })` with current profile values.
10. Domain errors (`DomainError`) must be shown calmly (e.g. "Dokładam" tapped just after rollover closed the challenge).
11. Not provided by the domain: overtime arc progress and remaining seconds (derive from `overtimeBlockStartedAt` / `targetAt` in the UI); an open challenge is an `empty` row in `timelineRows`.

**Open decisions for plan 3 (owner):**

- S12 colours: `timelineRows` never marks an interrupted attempt as `record`, while the record statistic and the "Nowy rekord" badge do count it; a multi-day challenge is drawn only on its start day.
- Threshold badges are not awarded while a challenge is still running (a 24 h challenge at hour 13 has not yet earned the 12 h badge) — decide whether S05 should award them live.
- A first challenge started late in the evening with the default "22:00 yesterday" answer starts with ≥ 24 h smoke-free; the morning sheet should handle evening starts.
- Template leftovers to replace: `App.tsx`, `index.ts`, `app.json` / `package.json` name and slug `app`, default icons; bundle ids in plan 6.

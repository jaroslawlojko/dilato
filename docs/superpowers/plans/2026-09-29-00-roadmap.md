# Dilato MVP — Implementation Roadmap

**Spec:** `docs/superpowers/specs/2026-09-29-dilato-mvp-design.md`

The MVP is split into six plans. Each one ends with working, tested software and is written in full just before it is executed, so it can use what the previous plans actually produced.

| # | Plan | Delivers | Depends on | Status |
|---|---|---|---|---|
| 1 | **Foundation & domain core** (`2026-09-29-01-domain-core.md`) | Expo app skeleton, Jest in `Europe/Warsaw`, the complete pure `src/domain`: time, ladder, suggestion, challenge state machine, smoke-free, body benefits, stats, badges, celebration tier | — | written |
| 2 | Local data & app services | `expo-sqlite` schema + migrations; repositories for profile, challenges, cravings and badges; outbox write path (no network yet); `ChallengeService` that applies domain transitions, persists them and awards badges. Tested in Jest with an in-memory SQLite adapter | 1 | to write |
| 3 | UI system & core screens (offline) | Tokens, fonts, components, `HorizonClock`; `expo-router`; onboarding steps 2–3 with a local profile; tabs S03/S10/S11/S12; challenge flow S04–S09 + morning question; settings (local parts); light/dark theme; PL i18n. A fully usable offline app in a dev build | 2 | to write |
| 4 | Backend, auth & sync | Supabase migrations, RLS + isolation tests; auth screens; onboarding "Krok 1 z 3 — Konto" with GDPR consents; sync engine (outbox push, pull, LWW); full pull on login; logout; data export; `delete-account` Edge Function | 2, 3 | to write |
| 5 | Platform features | Local notifications with the daily cap; iOS Live Activity (Swift target); Android ongoing notification; large celebration + share card; haptics; "Nadal trwa?" sheet; deep links | 3 | to write |
| 6 | EN localisation, E2E & release | EN copy in i18n; Maestro flows; EAS build profiles; store assets and listings; launch checklist (medical review, privacy policy, Data Safety, privacy labels) | 1–5 | to write |

## Environment notes

- **Development machine:** Windows 11, Node 24, no Mac.
- **iOS builds:** made with **EAS Build (cloud)** and tested on a physical iPhone via a development build. The Live Activity (plan 5) can only be verified on a real iPhone.
- **Android:** emulator + local Maestro runs.
- **iOS E2E:** runs through EAS workflows / Maestro Cloud, or manually.
- **Git:** the repo is on a drive without ownership info. Always run `git -c safe.directory=F:/DATA_1/CC/Projekty/Dilato …`.
